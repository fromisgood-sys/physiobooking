# Decisions

Judgement calls made where the spec or DESIGN.md was silent or where tooling had moved on since they were written.

- **Tailwind v4, not `tailwind.config.ts`.** `create-next-app@latest` installs Tailwind v4, which is CSS-first (`@theme` in `app/globals.css`) and has no `tailwind.config.ts` by default. DESIGN.md's tokens are defined there instead — same tokens, same discipline (no default Tailwind colour names, no default radii), different mechanism.
- **shadcn/ui `base-nova` style.** The installed shadcn CLI (v4) defaults to a Base UI (`@base-ui/react`) primitive layer rather than Radix, with a separate `cn` package. Used as installed; all shadcn semantic tokens (`--primary`, `--border`, `--ring`, etc.) are remapped to DESIGN.md's palette so generated components inherit the clinical look instead of shadcn's neutral default.
- **Dark-mode status colours.** DESIGN.md gives light-mode-only hex values for `state.ok/warn/danger`. Dark-mode variants were chosen to keep the same hue and AA contrast against `carbon` grounds; not specified in DESIGN.md.
- **Git repository initialised.** The project had no git repo. Initialised one locally; nothing has been pushed anywhere.
- **`middleware.ts` → `proxy.ts`.** Next.js 16 deprecated the `middleware` file convention in favour of `proxy` (same behaviour, new filename/export name). Migrated immediately since it's a mechanical rename and the deprecation warning would only get louder later.
- **Day strip, not a month calendar.** physio-booking-app-spec.md section 6 says "calendar month view" for `/book/[physioId]`, but DESIGN.md's component rules explicitly design a horizontal day strip for this exact screen and DESIGN.md wins on UI shape per CLAUDE.md. Implemented as a 30-day scrollable strip starting today; a day is muted when its weekday has no availability rule at all, a fully-booked day still shows in the strip but yields the "No times available on this day" empty state once selected.
- **`lime.soft` token invented.** DESIGN.md's Summary Bar component rule calls for a `lime.soft` background, but the colour token table only defines `lime.DEFAULT` and `lime.ink`. Added a light lime tint (`#F4F9DC`, dark-mode `#242A0F`) following the same tint pattern as `azure.soft`.
- **Seed physiotherapist ids fixed to be RFC 4122 v4-conformant.** The first draft used memorable repeating-digit ids (`11111111-1111-1111-1111-111111111111`); zod v4's `.uuid()` strictly checks the version/variant nibbles and rejected them, which would have made every seeded physio unbookable through the real API. Reissued as `11111111-1111-4111-8111-111111111111`-style ids (version nibble `4`, variant nibble `8`). Real `gen_random_uuid()` rows are unaffected.
- **Untyped Supabase client mis-infers to-one embeds as arrays.** Without generated `Database` types, `supabase-js` types an embedded `physiotherapists(...)` relation on `appointments` as an array, even though PostgREST returns a single object at runtime (the FK lives on `appointments`, so it's genuinely to-one). Fixed by casting the query result to the correct shape at the two call sites (`app/api/appointments/[id]/route.ts`, `app/appointments/page.tsx`) rather than indexing `[0]`, which would have silently broken at runtime. Proper fix (generating types) is in `docs/BACKLOG.md`, blocked on the same missing Supabase access token as the migration push.
- **"Per-physiotherapist load" = this week's non-cancelled bookings.** Spec section 6 names this stat without defining its window. Scoped it to the same week as the "appointments this week" tile for a coherent snapshot, rather than all-time totals.
- **Fixed a patient-email bug surfaced by admin editing.** `PATCH`/`DELETE /api/appointments/[id]` sourced the "patient" notification email from the *caller's own* `user.email` — harmless while only a patient could reach their own booking, but wrong the moment an admin cancels or edits on a patient's behalf (it would have emailed the admin instead of the patient). Fixed to always read the appointment owner's email from `profiles`.
- **Cancel stays on `DELETE`, not `PATCH status:"cancelled"`.** The admin edit schema deliberately excludes `"cancelled"` from its status enum — the existing `DELETE` handler already does the full soft-cancel (calendar delete + notify) and admin row actions reuse it, rather than duplicating that logic behind a second path.
- **Notes-only admin edits don't email the patient.** `notes` is an admin-only internal field; only a time/physio change or a status change (completed/no-show) triggers `notifyAppointment`.
- **Export filename falls back to "all".** Spec's `appointments_<from>_to_<to>.xlsx` assumes a date range is always set; when the admin exports without one, `<from>`/`<to>` become the literal string `all` rather than inventing a date range.
- **No hard-delete endpoint for physiotherapists at all.** Spec says "never hard-delete if appointments exist" — rather than checking for existing appointments before allowing a delete, the admin API simply never exposes a delete; deactivate (`is_active = false`) is the only removal path, which trivially satisfies the constraint.
- **Availability rules replaced via delete-then-insert, not a single transaction.** `PUT /api/admin/availability` deletes a physio's existing weekly rules and reinserts the new set as two sequential Supabase calls. There's a small window where a concurrent slot-generation read could see zero rules; acceptable for an admin tool edited infrequently and not mid-booking-rush.
- **`state.warn` darkened from DESIGN.md's literal hex.** `#B0791B` (as specified) is ~3.75:1 against white/paper as normal-size text — below the 4.5:1 AA minimum DESIGN.md itself requires ("WCAG AA on every pair"). Used `#8F5F13`, same hue, ~5.5:1. Also switched a few small `text-azure` UI links (13-15px, not "large text" by WCAG's definition) to `text-azure-hover`, which passes AA at ~5.1:1 where the base `azure` only reaches ~3.85:1 — `azure` itself stays correct for white-on-azure button fills and large numerals, where it already passes.
- **Automatic dark mode via a pre-hydration script**, not a manual toggle. `app/globals.css`'s `.dark` class selector needs something to add that class; spec only asks for "light and dark mode," not a switch, so `app/layout.tsx` sets `.dark` from `prefers-color-scheme` before first paint (avoids a flash of the wrong theme). A manual toggle can layer on top later without CSS changes.
- **Global `:focus-visible` outline in `app/globals.css`** rather than per-component ring classes, so DESIGN.md's "visible 2px azure.ring focus ring" requirement can't be missed on any one button as new components get added.
- **Dropped `backdrop-blur` from the shadcn `Dialog` overlay.** The installed shadcn dialog primitive ships `backdrop-blur-xs` on its scrim by default; DESIGN.md bans backdrop-blur outright with no scrim exception, so it's removed (plain `bg-black/20`).
- **Hero heading wasn't scaling to desktop size.** DESIGN.md's type table gives the hero two sizes (44/48 mobile, 60/62 desktop); `app/page.tsx` only implemented the mobile one. Caught via an actual browser screenshot, not the automated tests (which don't check rendered type scale) — added the `lg:text-[60px] lg:leading-[62px]` variant.
- **`playwright` added as a devDependency** for real browser-driven verification (screenshots, redirect behaviour, console errors) alongside the Vitest unit suite. Its Chromium binary is a large download; this sandbox's network only reached it via the `cdn.playwright.dev` host, not Playwright's default — worth knowing if a fresh `npx playwright install` ever hangs here again.
- **`appointments.ends_at`/`slot` changed from generated columns to a trigger.** The original migration used `generated always as (starts_at + interval '45 minutes') stored` — Postgres rejects this at `CREATE TABLE` time with `42P17: generation expression is not immutable`, because `timestamptz + interval` is classified `STABLE` (it depends on the session's `TimeZone` setting), even for a fixed interval like 45 minutes. Fixed by making both plain `not null` columns populated by a `BEFORE INSERT OR UPDATE OF starts_at` trigger (`compute_appointment_slot()`) instead — functionally identical from the app's side, since nothing in the codebase ever set `ends_at`/`slot` explicitly either way. Caught when the user ran the migration against the real project; never surfaced locally since nothing in this build exercises DDL against a live Postgres instance.
- **`/book` and `/book/[physioId]` are public, overriding the spec.** physio-booking-app-spec.md section 5 explicitly says "Middleware protects `/book`, `/appointments`, and `/admin`." This was changed on direct user instruction after research confirmed forcing sign-in before browsing is a known conversion killer for booking flows (Calendly/Booksy-style products all let you browse first). Sign-in is now required only at the confirm step (`/book/[physioId]/confirm`), which preserves the exact date/time selection through the OAuth round-trip via a `next` redirect param. `/appointments` and `/admin` remain fully gated — this only relaxes the browsing steps. Needed new RLS policies granting the `anon` role read access to `physiotherapists` and `availability_rules` (migration `0003_public_browsing.sql`); `appointments` RLS is untouched, so anonymous visitors still can't read or write bookings.
- **Unavailable slot ≠ booked vs. out-of-hours.** The slot grid renders the full theoretical 08:00–16:15 grid and marks anything the API didn't return as unavailable (strikethrough), without distinguishing "already booked" from "outside this physio's configured hours." All seeded physios use the same 08:00–17:00 window, so this doesn't currently show; worth revisiting if a physio ever gets shorter hours.
